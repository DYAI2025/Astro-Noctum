## Context

Bazodiac features span two targets: **web** (`src/`) and **mobile** (`apps/mobile/`). Both follow the same 5-step loop. Arguments tell us what to build and where.

## Your Task

Execute the full feature development loop from brief to shipped commit.

### Steps

1. **Understand the brief** — The user's argument (or current conversation) describes what to build. Identify:
   - Target: `web`, `mobile`, or `both`
   - Scope: component, hook, API endpoint, quiz, etc.
   - Any relevant CLAUDE.md context (routes, modules, conventions)

2. **Select domain skills** — Invoke the appropriate skill BEFORE writing any plan:
   - Web UI: `ui-ux-pro-max` or `frontend-developer`
   - Web backend/API: `backend-development-feature-development`
   - Mobile: `mobile-design` or `react-native-architecture`
   - Both: invoke both in sequence

3. **Write implementation plan** — Invoke `superpowers:writing-plans` with the feature description. The plan must include:
   - Exact file paths (`src/` or `apps/mobile/src/`)
   - Bite-sized TDD steps (write test → fail → implement → pass → commit)
   - German UI text, English code identifiers

4. **Execute plan via subagents** — Invoke `superpowers:execute-plan` with argument `1. subagent`. Batch 3 tasks at a time, verify between batches:
   - Web: `npm run test` + `npm run lint`
   - Mobile: `npx tsc --noEmit` (from `apps/mobile/`)

5. **Code review** — Invoke `code-review-excellence`. Address all blocking findings before shipping.

6. **Ship** — Invoke `ship` to commit and push.

### Guardrails
- German UI text, English code identifiers — always
- New components need a test file in `src/__tests__/` (web) or colocated `__tests__/` (mobile)
- Never import from `features/plan/` into `src/`
- Shared types go to `packages/shared/` if used by both web and mobile
- Feature flags: new risky features default OFF (`localStorage.setItem('ff_<name>', 'false')`)
- Use Conventional Commits: `feat(AN-<id>): ...`
