## Context
Dashboard components live in `src/components/dashboard/`. Dark mode background is `#00050A` (obsidian). Bright mode uses CSS vars. WCAG 2.1 AA requires 4.5:1 for normal text, 3:1 for large text and UI components.

## Your Task

Run a comprehensive audit of all Dashboard components for visual consistency, accessibility, and i18n coverage.

### Steps

1. **List all Dashboard components:**
   ```bash
   ls src/components/dashboard/*.tsx src/components/CosmicWeatherCard.tsx src/components/ShareCard.tsx
   ```

2. **For each component, check:**
   - **Theme consistency:** All colors use CSS vars (`var(--tile-*)`) or Tailwind classes — no hardcoded hex on text
   - **WCAG contrast:** Text opacity >= 0.50 on dark backgrounds; calculate ratio for any custom colors against #00050A
   - **i18n coverage:** All user-visible strings use `t()` — no hardcoded DE/EN ternaries or raw strings
   - **Bright/Dark parity:** Component renders correctly in both modes (check for `bg-zinc-*` / `bg-[#0...]` that only work in dark)

3. **Calculate contrast ratios** using WCAG luminance formula for any failing pairs

4. **Generate audit report** as `docs/dashboard-audit-YYYY-MM-DD.md` with:
   - Pass/fail table per component
   - Before/after for each fix
   - Remaining marginal items

5. **Apply fixes** for all failures, run tests

6. **Update tasks.md** if this was triggered by a task

### Guardrails
- Never change semantic meaning of text — only visual properties
- Preserve existing hover/transition effects when adjusting opacity
- Test in both Dark and Bright mode after changes
- Don't fix things that are decorative (borders, shadows) — only text and interactive elements
