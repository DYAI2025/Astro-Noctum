## Context
Bazodiac (Astro-Noctum) — React 19 SPA with Express backend, Supabase, BAFE API, Fusion Ring canvas.
Dev briefs are often in German, stored as .docx in `features/plan/` or passed as file paths.
Plans are saved to `docs/plans/YYYY-MM-DD-<feature-name>.md`.

## Your Task

Process a specification document through the full pipeline: extract, audit, plan, execute.

### Steps

1. **Extract the spec**
   - If .docx: extract text via `python3 -c "import zipfile, re; ..."` (zip → word/document.xml → strip tags)
   - If .md: read directly
   - If pasted text: use as-is

2. **Audit current state**
   - For each requirement in the spec, check if it's already implemented
   - Use Grep/Glob to find relevant files and verify implementation
   - Produce a gap table: `| Requirement | Status | Files |`

3. **Write implementation plan**
   - Use `superpowers:writing-plans` skill
   - Save to `docs/plans/YYYY-MM-DD-<feature-name>.md`
   - Include exact file paths, code snippets, test commands

4. **Execute**
   - Ask user: "Subagent-driven (this session) or parallel session?"
   - If subagent: use `superpowers:executing-plans` — batch 3 tasks at a time
   - "proceed" / "go on" = continue next batch without questions

### Guardrails
- Always audit BEFORE planning — the spec may already be partially implemented
- .docx files in this repo are often mislabeled as .md — check for PK header bytes
- Plans go in `docs/plans/`, never in `features/plan/` (that's for specs)
- When user says "proceed", execute next batch immediately
