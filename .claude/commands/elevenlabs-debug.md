## Context

The ElevenLabs voice agent (Levi / Eve) calls tools via superglue webhooks. The integration has three layers:

1. **ElevenLabs Dashboard** — tool parameter sources (Dynamic Variable vs conversation_initiation_client_data)
2. **Superglue** (`bazodiac-elevenlabs-context`) — webhook that queries Supabase: profiles + astro_profiles + agent_conversations
3. **Server** (`server.mjs`) — `/api/profile/:userId` endpoint (protected by `ELEVENLABS_TOOL_SECRET`)

Common failure modes: wrong user data returned, "Missing required dynamic variables", tool 100% error rate, authorization failures.

## Your Task

Systematically diagnose the ElevenLabs tool integration failure.

### Steps

1. **Identify the symptom** — ask which agent (Levi / Eve) and what the exact error is:
   - "Missing required dynamic variables: {'conversation_id', ...}"
   - Wrong user data returned (e.g. "Ben_Test_Dummy_Null")
   - Tool 100% error rate (e.g. `save_conversation_eve`)
   - Agent doesn't respond / loops on tool calls

2. **Check dynamic variable config** (user must verify in ElevenLabs dashboard):
   - `user_id` → Source: **Dynamic Variable**, Variable name: `user_id`
   - `conversation_id` → this is a **System Variable** injected by ElevenLabs automatically — do NOT configure it as a dynamic variable
   - Any other parameter using `conversation_initiation_client_data → metadata_items` is wrong

3. **Verify superglue webhook** — ask user to check last run in superglue dashboard:
   - Was `user_id` a valid UUID (not null, not "test")?
   - Status: SUCCESS or ERROR?
   - Which step failed (profiles query, astro_profiles query, agent_conversations)?
   - `requestSource: webhook` confirms ElevenLabs triggered it correctly

4. **Check Authorization secrets** — for each failing tool:
   - `get_user_astro_profile` → Secret should be `wsec_...` (ELEVENLABS_TOOL_SECRET)
   - `save_conversation_eve` → same Secret as above — NOT `BAZODIAC_ENGINE`
   - If Secret name says `BAZODIAC_ENGINE`, change it to the correct ELEVENLABS_TOOL_SECRET secret

5. **Check if fix branch is deployed**:
   ```bash
   git log --oneline origin/main | head -5
   git branch -r | grep fix/bug-23
   ```
   If the ElevenLabs fix is on a feature branch not yet merged, production still has the old broken behavior.

6. **Test the endpoint directly** — with a known user UUID:
   ```bash
   curl -s "https://bazodiac.space/api/profile/<uuid>" \
     -H "Authorization: Bearer <ELEVENLABS_TOOL_SECRET>" | head -100
   ```
   Expected: JSON with `display_name`, `birth_date`, `zodiac_sign`, etc.
   - 404 → route not deployed yet
   - 500 → UUID format issue or Supabase query error
   - 401 → wrong secret

7. **Check Railway deployment** — if endpoint returns 404 or wrong data:
   - Was the latest commit pushed and Railway rebuilt?
   - Check Railway logs for startup errors

### Guardrails

- `conversation_id` is NEVER a dynamic variable — ElevenLabs injects it as a system variable automatically. Do not configure it.
- `BAZODIAC_ENGINE` is NOT the correct secret name for ElevenLabs tool authorization — find the correct `ELEVENLABS_TOOL_SECRET` value.
- superglue (`bazodiac-elevenlabs-context`) is the real backend for `get_user_astro_profile` — not `/api/profile/:userId` directly.
- If user data is wrong (old profile / dummy data), first check whether the ElevenLabs fix branch has been merged to main and deployed.
- The fix branch must be merged AND Railway must rebuild before production sees the fix.
