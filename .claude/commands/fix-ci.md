## Context
CI runs TypeScript checks (`npx tsc --noEmit`) and tests (`npm run test`) on GitHub Actions. Deployments go to Railway via nixpacks. The user pastes error output directly.

## Your Task

Fix the CI or deployment failure.

### Steps

1. **Parse the error** — Extract the failing step, file, and error message from the pasted output.

2. **Diagnose locally** — Run the same command locally:
   - TypeScript: `npx tsc --noEmit 2>&1 | grep "^src/"`
   - Tests: `npx vitest run`
   - Build: `npm run build`
   - Railway: check `nixpacks.toml` and `server.mjs`

3. **Check remote vs local divergence** — If local passes but CI fails:
   - `git show origin/<branch>:<file>` to see what CI actually has
   - Check if a fix was committed locally but not pushed
   - Check for "Potential fix" commits from Copilot Autofix that may conflict

4. **Fix** — Apply the minimal fix. Common patterns:
   - Zod schema type mismatch → define explicit schema matching the interface
   - Missing file on branch → `git show origin/main:<path>` and restore
   - Import error → check path aliases (`@/*` = project root)
   - Build failure → check `nixpacks.toml` install/build commands

5. **Verify locally** — `npx tsc --noEmit` + `npm run test` must both pass.

6. **Push** — `git push origin <branch>`. If rejected, `git pull --rebase` first.
   Resolve conflicts if needed, never force-push.

### Guardrails
- Always verify the remote file content before assuming local state matches
- If Copilot Autofix commits exist on the branch, check if they introduced conflicts
- Never use `--no-verify` or `--force`
- After push, inform the user of the commit hash
