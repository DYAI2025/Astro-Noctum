## Context

Run after completing a batch of implementation work on Bazodiac. Orchestrates the full review ceremony that the user otherwise runs as 4-5 separate commands (/code-reviewer, /codex-review, /code-review-checklist, /code-review-excellence).

## Your Task

Run a complete post-implementation review and prepare to ship.

### Steps

1. **Test suite**
   ```bash
   npx vitest run 2>&1 | tail -5
   npx tsc --noEmit 2>&1 | head -10
   ```
   If any tests fail — stop here, report failures, do not proceed.

2. **Diff summary**
   ```bash
   git diff main...HEAD --stat 2>/dev/null | tail -3
   git log main..HEAD --oneline 2>/dev/null
   ```

3. **Code review** — analyse the diff against these dimensions:
   - **Functionality**: edge cases, error handling, guard clauses
   - **Security**: injection, XSS, unguarded env vars, exposed secrets
   - **Performance**: N+1 queries, missing caches, blocking async
   - **Code quality**: naming, single responsibility, dead code, console.log
   - **Tests**: new code covered, ACs verified, regressions guarded
   - **Schema/migration alignment**: if SQL changed, both files must agree
   - **i18n**: UI strings must go through `t()`, never hardcoded German

4. **CHANGELOG check**
   - Is `CHANGELOG.md` updated for today's work?
   - If not, propose the missing entry (Features / Bug Fixes / Refactoring / Database sections).

5. **Verdict**
   - List findings grouped: Critical → Important → Minor
   - State overall verdict: Ready to ship / Needs fixes first

6. **Offer to ship**
   - If verdict is "Ready": ask "Ship it? (yes/no)"
   - If yes: invoke `/ship` workflow (stage relevant files, commit, push)

### Guardrails
- Never ship if any test fails
- Never skip the security check even for "small" changes
- Schema changes: always verify supabase-schema.sql matches the migration
- Display name / user data: verify DEC-display-name-db-only is respected (never in FuFirE payload)
