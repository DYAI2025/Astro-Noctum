## Context
The Bazodiac onboarding has a multi-phase flow: Splash -> AuthGate -> BirthForm -> SignatureReveal -> Dashboard. The tour overlay (4 steps) runs on first Dashboard visit. State is persisted in both localStorage and Supabase `profiles` table.

## Your Task

Reset onboarding state for a user, then verify the full flow works correctly.

### Steps

1. **Reset state** — clear both persistence layers:
   ```sql
   -- Supabase: reset tour + daily modal
   UPDATE profiles SET tour_completed = false, daily_modal_seen = false WHERE email = '<user-email>';
   ```
   ```js
   // Browser console (if available):
   localStorage.removeItem('bazodiac_tour_completed');
   localStorage.removeItem('ff_signature_onboarding_v1');
   ```

2. **Open fresh browser session** — use chrome automation or instruct user to open incognito.

3. **Test each phase**:
   - Splash screen loads, no flash of content
   - Auth gate: sign up or sign in works
   - BirthForm: date/time/location entry, Nominatim search functional
   - SignatureReveal: ring renders (V2 or V1 fallback), profile summary shows, quiz question appears
   - Dashboard: tour overlay appears at step 0, progresses through all 4 steps
   - Tour step 2 (Levi): shows correctly, "JETZT SPRECHEN" and "SPAETER" buttons work
   - After tour: Levi call button is clickable, no overlays blocking

4. **Check for regressions**:
   - No `overflow: hidden` left on body after tour
   - Premium status correctly detected
   - ElevenLabs widget loads (check CSP in console)
   - No `ERR_INTERNET_DISCONNECTED` cascading failures

5. **Fix any bugs found** — commit with `fix(AN-FTE):` prefix

### Guardrails
- The `tour_completed` column must exist in profiles table — if missing, add it
- `useDashboardTour` must skip tour on Supabase error (not start it)
- `usePremium` must keep last known state on network error
- Tour overlay uses `fixed inset-0 z-[100]` — any bug here blocks the entire UI
- Always test with both fresh user and existing user
