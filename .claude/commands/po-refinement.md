## Context
The project uses SDLC scaffold with requirements in `1-objectives/requirements/`, decisions in `2-design/decisions/`, and the objectives index in `1-objectives/CLAUDE.objectives.md`. Tasks with "NEEDS REFINEMENT" in Notes require product decisions before implementation.

## Your Task

Collect open product questions from tasks.md, present them as structured multiple-choice to the user, and record the decisions.

### Steps

1. **Scan tasks.md** for tasks with "NEEDS REFINEMENT" in the Notes column
2. **For each question, present as A/B/C/D options** with:
   - Clear description of each option
   - Trade-offs (effort, UX impact, technical complexity)
   - Your recommendation if one option is clearly better
3. **Wait for user answers** — one question at a time or batch
4. **Record decisions:**
   - Create `DEC-*.md` file in `2-design/decisions/` for each decision
   - Update affected requirement files if acceptance criteria change materially
   - If a requirement changes materially: revert Status from Approved → Draft
   - Update `1-objectives/CLAUDE.objectives.md` index rows accordingly
5. **Update tasks.md:**
   - Remove "NEEDS REFINEMENT" prefix from resolved task Notes
   - Add reference to the new DEC-* decision
6. **Report summary:**
   - Decisions recorded
   - Requirements affected (status changes)
   - Tasks unblocked

### Guardrails
- Never decide unilaterally — always present options and wait
- Revert Approved → Draft when acceptance criteria change materially (lifecycle consistency)
- Always present the trade-off between effort and user value
- If a question has monetization implications, explicitly flag it
- Reference existing decisions that may constrain the options
