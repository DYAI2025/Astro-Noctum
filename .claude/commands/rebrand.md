## Context
This project has German UI text but English code identifiers. Rebranding must ONLY touch user-facing strings.

## Your Task

Rename `$ARGUMENTS` (format: "Old Name" "New Name") across user-facing text only.

### Steps

1. **Parse arguments**: Extract old name and new name from the arguments.

2. **Find all occurrences**
   ```
   Grep for the old name (case-insensitive) across src/, public/, CLAUDE.md
   ```

3. **Classify each occurrence**
   - **User-facing**: JSX text content, aria-labels, alt text, route paths, page titles, button labels, meta tags, i18n strings, data display text, article content
   - **Code-internal**: variable names, function names, import paths, type names, file names, CSS class names, component names, hook names, context names

4. **Apply renames** — ONLY to user-facing occurrences. Use Edit tool for each file.

5. **Verify**
   - `npm run lint` — no new errors
   - `npm run build` — succeeds
   - Grep for remaining old-name occurrences and confirm they're all code-internal

6. **Report** — show what was changed and what was intentionally kept.

### Guardrails
- **NEVER rename code identifiers** — variable names, imports, function names, type names, file names
- **NEVER rename** CSS classes, component names, hook names (e.g., `useFusionRing` stays even if "Fusion Ring" is rebranded)
- Route paths in `router.tsx` ARE user-facing — rename those
- Comments in English are code-internal — don't rename
- When in doubt, DON'T rename — ask the user
