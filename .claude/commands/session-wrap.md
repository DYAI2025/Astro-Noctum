## Context

At the end of a development session, three things should always happen: documentation is updated to reflect changes made, context is compacted to free up the window, and work is shipped to remote. This skill chains all three.

## Your Task

Wrap up the current development session cleanly.

### Steps

1. **Assess what changed** — Run `git diff --stat HEAD` and `git status` to see what was modified since the last commit. Identify:
   - New components, hooks, or modules → need entries in CLAUDE.md "Key Modules" table
   - New routes → need entries in CLAUDE.md "Routes" table
   - New environment variables → need entries in CLAUDE.md "Environment Variables" section
   - New Supabase tables or migrations → need entries in `supabase-schema.sql` comments

2. **Update documentation** — Make the minimal necessary doc updates:
   - `CLAUDE.md` for architectural additions (new modules, routes, flags)
   - `docs/` for significant feature docs (only if the feature warrants it)
   - Do NOT write new README files or rewrite existing docs — only add what's missing

3. **Compact** — Invoke `superpowers:context-compression` or `/compact` to summarize the session and free context window. Skip this step if context usage is below 50%.

4. **Ship** — Invoke `ship` to stage, commit, and push any remaining uncommitted changes. If nothing is uncommitted, skip.

### Guardrails
- Only update docs for things that actually changed in this session
- Do not add speculative or planned-but-not-implemented information to CLAUDE.md
- Commit message for doc-only changes: `docs: update CLAUDE.md for <feature-name>`
- Never force-push; always verify `git status` is clean after push
