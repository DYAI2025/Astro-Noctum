## Context
Bazodiac sprints follow a fixed pipeline. Sprint briefs live in `/Users/benjaminpoersch/Projects/codebase/Sprints/`. The user expects parallel subagent execution, batch commits, and a PR at the end.

## Your Task

Execute a complete sprint from brief to PR.

### Steps

1. **Load sprint brief** — Read the file passed as argument (e.g. `/sprint07/SPRINT_BRIEF.md`). If no path given, ask.

2. **Write implementation plan** — Invoke `superpowers:writing-plans` with the brief content + relevant context skills (`/ui-ux-pro-max`, `/backend-dev-guidelines`, etc. as appropriate).

3. **Create feature branch** — `git checkout -b feature/sprint<NN>-<slug>` from latest main.

4. **Execute plan via subagents** — Choose mode based on sprint size:
   - **≥3 work packages (preferred):** Invoke `orchestration:orchestration` with the SPRINT.md path. The orchestrator dispatches 2 parallel agents per WP batch, commits between batches, and runs code review autonomously.
   - **1–2 work packages (simpler sprints):** Invoke `superpowers:executing-plans` with argument `1. subagent`. Batch 3 tasks at a time, verify between batches.
   - Always verify between batches: `npm run test` + `npm run lint`

5. **Verify** — Run `npm run test` (all must pass) and `npm run lint` (clean).

6. **Ship** — Invoke `/ship` to commit and push.

7. **Create PR** — Use `superpowers:finishing-a-development-branch` to present options (push, PR, merge).

### Guardrails
- Always create a feature branch — never commit sprint work directly to main
- Run full test suite between batches, not just at the end
- Use Conventional Commits with sprint ticket IDs: `feat(AN-S<NN>): ...`
- P2 features default ON, P3 features default OFF in feature flags
- German UI text, English code identifiers
