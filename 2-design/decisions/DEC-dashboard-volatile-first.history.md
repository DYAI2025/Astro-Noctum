## Alternatives considered

### Option A: User-configurable section order
- Pros: Personalization; advanced users could promote static content
- Cons: Destroys the daily-use value proposition; most users would not configure anything; adds state management complexity

### Option B: Algorithm-driven ordering based on today's planetary intensity
- Pros: Most relevant content truly first
- Cons: Order becomes unpredictable and untestable; brand messaging relies on a consistent first impression

### Option C: Fixed volatile-first order (chosen)
- Pros: Predictable, testable, clear product contract; daily-use value proposition is always realized
- Cons: Less flexible for edge cases where natal data might feel more relevant

## Reasoning

The dashboard's daily-use value depends entirely on showing something different every day. If the first viewport contains only static natal data, there is no reason to return. The volatile-first order enforces the product's core promise. The ordering is simple enough to explain to any stakeholder in one sentence.
