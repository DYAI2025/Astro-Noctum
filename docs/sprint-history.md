## 2026-04-18 — Root Cause identifiziert + Hotfix-Sprint angelegt

Follow-up-Query auf `soulprint_sectors` zeigte 50/50 prod users mit NULL. Code-Inspection von `server.mjs` im Soulprint-Persistenzpfad enthüllte Race Condition: `.update().eq('user_id')` statt `.upsert()` scheitert für 100% der User, weil die `astro_profiles`-Zeile erst nachgelagert durch den Superglue-Worker erstellt wird. Frontend lädt NULL → Default-Signatur für alle. Neuer Mini-Sprint **S-SOULPRINT-HOTFIX** angelegt (6 Tasks über 3 Phasen), geht S-SUPERGLUE-STAGE1 voraus: GOAL-soulprint-persistence (Approved), REQ-REL-soulprint-persist-onboarding (Approved), Tasks TASK-sphx-bootstrap-upsert → TASK-sphx-verify-no-overwrite → TASK-sphx-unit-test → TASK-sphx-backfill → TASK-sphx-integration-test → TASK-sphx-po-report.
